Verification of the FE code

Every test case that has been run against fem/: what it checks, what it is compared with, and the result as logged. Numbers are copied from the logs in verification/results/ and cmm/results/.

Material in the FE tests unless stated: neo-Hooke \(C_{10} = 0.305\) MPa, \(K = 6.1\) MPa. Errors are relative unless units are given. Elements: hex8, tet10, tet4; formulations standard, fbar, hybrid (Q1/P0, P2/P0), hybrid_p1 (P2/P1).

Not an FE result

Our Python HCMM vs Maes' UMATs differ by up to 2 % in most cases, 3–5 % for B/C HCM and 9–18 % for C/F (force control with growth). The FE code reproduces Abaqus exactly with the same UMAT, so this is a difference in the material model, not in the FE code. It is explained by three implementation differences (below): with Maes' choices, B and C agree to ≤ 0.1 % (see cmm/results/modeling_history.md, 2026-10-22 and 2026-10-27).

Time-step study of the largest gap (C / F / HCM)

Both codes converge at first order, but to different limits, and the gap grows slightly as \(\Delta t \to 0\). The difference is therefore not the time integration or the explicit update. Both codes update the masses explicitly (forward Euler, stress from the start-of-step state); ours solves only \(F_r\) semi-implicitly. It is a difference in the model formulation. The fully implicit HCMM (hcmm.core_implicit) does not converge at the material point for this case (equilibrium Newton fails at every \(\Delta t\)), so it could not be used as a third reference.

  • Same element (C3D10 = fem tet10 standard): the difference drops from 1e-6 / 1e-4 to 3e-8 when Abaqus is converged as tightly as fem. The remaining difference with default settings is Abaqus' Newton tolerance, not a discretization difference.
  • Tension with C3D8H: homogeneous, so F-bar and Abaqus' compressible hybrid are both exact; agreement 1e-6 (odb single precision).

11. Assessment against Roache (2002)

Roache, Code Verification by the Method of Manufactured Solutions, J. Fluids Eng. 124:4–10 (.context/verification). He separates three activities, to be done in this order:

activitymeaninghere
code verificationerror evaluation against an exact solution under systematic refinement§1–7 (MMS, Lamé, exact homogeneous solutions, consistency), §8.1
calculation verificationerror estimation for one application, e.g. GCI§8.2 (artery G&R: mesh and time step)
validationagreement of the model with experimentsnone yet

The Abaqus runs (§9) are code-to-code comparisons. In Roache's terms they are confirmation rather than verification, but they are the only independent check of the Abaqus interface and its input handling.

Reading

Where both starts converge on the asymptotic meshes, the answers agree. The order of accuracy therefore does not depend on starting at the exact solution. The coarsest Q1/P0 growth mesh has more than one discrete equilibrium (pre-asymptotic: rate 2.59 there). This is the non-uniqueness Roache warns can give a false negative. The finest mesh shows a robustness limit of the solver for a large jump in prescribed displacement in one step, not an accuracy error (with load steps it is the normal use case).

12. Not covered / known gaps

  • Compressible hybrid element (perturbed Lagrangian, Abaqus C3D8H with finite \(K\)) is not implemented. Such inputs run as F-bar, which is exact for homogeneous deformation only.
  • F-bar in long G&R runs with \(K/\mu \gtrsim 10^3\): hourglass-type modes, Newton fails. Not fixed; use hybrid.
  • Q1/P0 is not inf-sup stable (Schur eigenvalue ratio ~ h² in Cook); it converges in all tests above.
  • Arc length and stability freeze the G&R state and are not differentiable; verified only on the column and arch.
  • No independent code for G&R on a real vessel geometry: the Abaqus comparisons are single-element (Maes) and box meshes. Bifurcation and tortuosity results are checked only through mesh/time convergence and the tests above.
  • Not in the code, so not tested: inertia, contact, two-way fluid coupling within a step.
